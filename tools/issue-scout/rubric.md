# Rubric: is this a good first issue?

## Checks


| Check                         | Evidence                                                                                                                                                                                                                                                                                        | Pass condition                                                                                                                                        | Weight    |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| Repo is active                | In the eval bundle, under Repo facts, look at when the most recent commit is in relation to the captured date in the "last 5 default-branch commits" line. / In github.com, in the main repo, go to "commits" and view when the last 5 commits are made to the "main" branch compared to today. | The last merge to the default branch happened within the last 30 days.                                                                                | required  |
| Repo is very active           | In the eval bundle, under Repo facts, look at when the most recent commit is in relation to the captured date in the "last 5 default-branch commits" line. / In github.com, in the main repo, go to "commits" and view when the last 5 commits are made to the "main" branch compared to today. | The last merge to the default branch happened within the last 10 days.                                                                                | preferred |
| Issue replies are timely      | In the eval bundle, under Repo facts, look at how many days it took a maintainer to comment in the "maintainer first-response sample" line. / In github.com, in the repo's issues page, go to recent activity, and view when the last updates were made compared to today.                      | The time between a PR request and a reply must be 7 days maximum. This passes if a majority (not all) of issues are responded within a timely manner. | preferred |
| Repo has a recent release     | In the eval bundle, look at the date in the "latest release" line in relation to the captured date. / In github.com, in the main repo page, see the right sidebar under "Releases" and get the date of the latest release compared to today.                                                    | The repo has a release within the last 60 days                                                                                                        | preferred |
| Repo is not archived          | In the eval bundle, in Repo facts, the value for "archived" is listed at the "repo:" line. / In github.com, determine if an orange banner is visible indicating that the repo is archived.                                                                                                      | The repo does not have a flag indicating it is archived                                                                                               | required  |
| Repo is popular               | In the eval bundle, in Repo facts, the number of the stars is listed at the "repo:" line. / In github.com, in the main repo page, at the top right of the page, see the number of stars listed.                                                                                                 | The repo has at least 1000 stars                                                                                                                      | preferred |
| Issue is not an umbrella      | In the eval bundle, check the content the Issues section, and possibly the problem and proposed changes sections. / In github.com, in the issue page, check the content of the entire issue.                                                                                                    | The issue concerns one piece of work, or has clear specs on what to update, not a codebase-wide issue.                                                | required  |
| Issue is not a tracking issue | In the eval bundle, check the content the Issues section, and possibly the problem and proposed changes sections. / In github.com, in the issue page, check the content of the entire issue.                                                                                                    | The issue does not indicate that it is a tracking issue nor a megaissue.                                                                              | required  |
| Issue is not difficult        | In the eval bundle, under the Repo facts section, see linked PRs in the "this issue" line. / In github.com, in the right sidebar under Development, see a list of pull request statuses there. A green icon means open, a red icon means closed, and a purple icon means merged.                | The issue does not contain two or more closed linked PRs while having zero merged PRs                                                                 | required  |
| Issue is small                | In the eval bundle, count the number of characters in the "Issue" section alone. / In github.com, count the number of characters in the entire issue.                                                                                                                                           | The length of the issue is 1000 characters or less                                                                                                    | preferred |
| Issue is not a usage question | In the eval bundle, look at the title of the issue and determine if it is a question or a statement. / In github.com, in the issue page, read the title of the issue and determine if it is a question or a statement.                                                                          | The title should not ask how to use the product, it should be a statement                                                                             | required  |
| Issue is unclaimed            | In the eval bundle, in Repo facts, see the value of "assignees" in the "this issue" line. / In github.com, in the issue page, look at the right sidebar and see if any assignees are listed.                                                                                                    | The issue must not currently have an assignee.                                                                                                        | required  |
| No open pull requests         | In the eval bundle, in Repo facts, see the value of "linked PRs" in the "this issue line". / In github.com, in the issue page under the title, see if there are any open PR requests next to the green open badge, if any.                                                                      | The issue must not have any open linked pull requests.                                                                                                | required  |
| AI code must be allowed       | In the eval bundle, look for AI use policies inside the CONTRIBUTING.md file. / In github.com, in the main repo, go to the CONTRIBUTING.md file.                                                                                                                                                | The CONTRIBUTING.md file must not have a statement that forbids AI-assisted code                                                                      | required  |


## Verdict rule

Only accept the issue if every required check passes. Any preferred checks should NOT change the verdict, rather, it should rank the issues instead. Any required check that is unclear must be treated as a fail.
